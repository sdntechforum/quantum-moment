# Chapter 11 verification record

The original harness was verified twice on 2026-09-24. The corrected harness
was rerun on 2026-10-28 on the authorized Ubuntu lab host with Docker 29.1.3.
The current retained results are from the corrected run, using the digest-pinned
Alpine 3.22.1 base and OpenSSL 3.5.8.

Observed results:

- the unchanged `agile_sign.sh` implementation passed with both policy files;
- Ed25519 produced a 64-byte signature;
- ML-DSA-65 produced a 3,309-byte signature;
- both signatures verified with the corresponding public key;
- the shell-syntax policy was rejected and created no marker file;
- the two hardcoded scripts had different source hashes; and
- no private-key file remained in the retained evidence tree.

The public keys and signatures differ between runs because key generation and
ML-DSA signing are randomized. The stable assertions are captured in
`results/verification.txt`; per-algorithm evidence is under `results/classical/`
and `results/post_quantum/`.

The corrected `run_all.sh` captured the agile implementation hash before the
Ed25519 and ML-DSA-65 policy runs, then compared it after both. The current
`results/verification.txt` records the passing assertion. The retained public
keys, signatures, and evidence files were regenerated by this run; no private
keys were retained.

Interpretation: the experiment verifies a narrow configuration and artifact
boundary. It does not establish production crypto-agility across key lifecycle,
stored data, protocols, peers, hardware modules, downgrade controls, or rollback.
